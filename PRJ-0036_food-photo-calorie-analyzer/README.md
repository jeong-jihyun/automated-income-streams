# PRJ-0036 음식 사진 칼로리 분석 앱 (추정 엔진)

음식 이름과 양(S/M/L 또는 g)으로 칼로리·영양을 '범위'로 추정하고, 사진이 너무 어둡거나 흐리면 다시 찍도록 알려 주는 명령줄 도구입니다. 음식 인식(AI)은 함수를 꽂아 쓰는 구조이며 이 도구에는 들어 있지 않습니다.

## 쓰는 법
```
python -m foodcal check-photo sample/meal_sharp.jpg
python -m foodcal estimate --item 쌀밥=M --item 김치=30g --log meals.json --date 2026-10-25
python -m foodcal day meals.json --date 2026-10-25
```

## 지키는 것
- 칼로리는 한 숫자가 아니라 범위(기본 ±25%, 인식 확신이 낮으면 ±40%)로 보여 줍니다.
- 확신이 낮은 음식은 '맞는지 확인해 주세요'로 사용자 확인을 요청하고, 목록에 없는 음식은 지어내지 않고 계산에서 뺍니다.
- 목표 칼로리·감량 조언·식단 지시 기능은 일부러 넣지 않았습니다(섭식 문제 위험). 모든 결과에 대략치 안내를 붙입니다.
- 사진은 점검만 하고 저장하지 않습니다.

## 확인한 것 (테스트 9개 통과)
추정 계산·범위·확신도 반영, 모든 음식 값의 칼로리-영양소 정합성, 목록에 없는 음식 처리, 양 입력 검증, 안내문(식단 조언 단어 없음), 사진 점검(어두움·작음·손상), 인식기 연결·오류 처리, 하루 기록, CLI.

## 확인하지 못한 것
- **영양 값 17개는 제가 아는 대략치이며 공식 자료가 아닙니다.** 식품의약품안전처 식품영양성분 DB 등으로 교체·검증이 필요하고, 같은 음식도 식당·집마다 크게 다릅니다.
- **실제 사진 인식은 하지 않았습니다**(인식기 미연결). 사진으로 칼로리를 맞게 추정하는지는 확인하지 못했습니다. 양 추정도 사용자가 고르는 S/M/L에 의존합니다.
- 음식 종류가 17개뿐이라 대부분의 식사는 목록에 없습니다.
- 앱 화면, 구독·광고, 구글 플레이 등록·건강 앱 정책 심사, 영양·의료 표현의 법적 검토
- 설계 문서(드라이브)는 읽지 않고 시트 한 줄 설명으로 범위를 잡았습니다.
