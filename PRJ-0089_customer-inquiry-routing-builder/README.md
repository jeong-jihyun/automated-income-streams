# 고객 문의 접수·분류 구축

고객 문의를 붙여 넣으면 키워드 규칙으로 담당 칸(배송·환불·교환·결제·사용법 등)에 나누고, 화난 표현·"오늘까지" 같은 기한 말로 긴급도를 매겨 칸별로 긴급한 순서로 보여 주는 휴대폰용 웹앱이에요. 인터넷이 없어도 돌아가고, 문의를 어디로 보내는 기능은 없어요.

## 쓰는 법
1. 앱을 열면 샘플 문의 8줄이 이미 들어 있고 결과가 바로 보여요.
2. 문의 칸의 글을 바꾸고 [분류하기]를 누르면 다시 계산해요. 한 줄이 문의 하나예요.
3. [분류 규칙 고치기]에서 `칸 이름: 키워드, 키워드` 형식으로 칸과 키워드를, 긴급도 단어도 고칠 수 있어요. 형식이 틀리면 빨간 글로 알려 줘요.
4. 입력과 규칙은 이 폰 안(localStorage)에만 저장돼요.

## APK 받아 설치하는 법
1. 이 폴더를 GitHub 저장소에 푸시해요.
2. 저장소의 GitHub Releases에서 `apk-PRJ-0089` 릴리스를 열고 `.apk` 파일을 폰으로 받아요.
3. 받은 파일을 눌러 설치해요.
4. "출처를 알 수 없는 앱" 설치를 막는다는 안내가 뜨면, 설정에서 그 앱(브라우저나 파일 앱)에 허용을 켠 뒤 다시 설치해요.

(APK 만드는 일은 이 폴더 밖 단계예요. 폰 없이 `app/index.html`을 브라우저로 열어도 똑같이 써 볼 수 있어요.)

## 시험 돌리기
```
node --test tests/test_all.js
```
(Node 22에서는 `node --test tests/`처럼 폴더 이름만 쓰면 오류가 나서 파일 이름까지 적어요.)

## 확인한 것 / 못 한 것
확인한 것
- 핵심 계산(`app/core.js`)의 시험 25개가 모두 통과했어요 (분류, 동점 처리, 긴급도 점수·상한, 일괄 처리, 칸별 정렬, 규칙 글 읽기·오류, 복사용 글).
- `index.html`의 화면 스크립트가 가짜 화면(node의 vm)에서 첫 실행, 입력 변경 후 재분류, 잘못된 규칙 오류 표시, 되돌리기, 저장소 막힘 상황에서 동작해요.
- 앱 파일 3개에 `http` 주소와 `fetch` 등 네트워크 호출이 없어요(시험으로 검사).

못 한 것
- 실제 폰 설치·화면 미확인 (실제 브라우저·폰에서 글씨 크기, 줄바꿈, 터치 동작을 눈으로 보지 못했어요).
- APK 만들기와 GitHub 푸시는 하지 않았어요.
- 키워드 방식이라 문장의 뜻은 몰라요. "화나지 않았어요"도 화난 표현으로 셀 수 있어요. 기본 키워드는 예시이고 실제 문의 자료로 맞춰 본 적이 없어요.
