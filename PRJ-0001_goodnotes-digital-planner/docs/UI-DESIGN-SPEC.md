# UI 설계서 — Goodnotes Digital Planner

- 문서 ID: PRJ-0001-UI-SPEC
- 버전: 1.0
- 상태: 설계 기준선(구현 전)
- 대상: React 18 + Vite, Electron 데스크톱, 반응형 웹 브라우저
- 관련 문서: [디자인 시스템](./DESIGN-SYSTEM.md), [모바일 대응 기획](../MOBILE-RESPONSIVE-PLAN.md)

## 1. 목적 및 범위

본 문서는 디지털 플래너 생성기의 정보 구조, 화면, 사용자 흐름, 상태, 반응형 동작과 웹·데스크톱 실행 경계를 정의한다. 본 문서는 설계 기준이며, 문서 반영만으로 UI나 웹 API가 구현되었다고 간주하지 않는다.

**필수 제품 방향:** Electron 전용 화면에 머물지 않고 PC·태블릿·스마트폰의 최신 웹 브라우저에서 사용할 수 있는 반응형 웹 UI를 제공한다. 웹에서 실제 PDF 생성까지 제공하려면 Python 엔진을 호출하는 서버 API가 별도로 구현되어야 한다.

## 2. 설계 원칙

1. 설정 → 검토 → 생성 → 결과 확인의 흐름을 명확하게 제공한다.
2. PC·태블릿·스마트폰에서 동일한 기능 구조와 일관된 UI를 제공한다.
3. UI와 PDF 생성 도메인 로직을 분리한다.
4. Electron 실행 경로를 유지하면서 웹 실행 경로를 추가한다.
5. 실제 생성 상태·진행률·검증 결과만 사용자에게 표시한다.
6. 실패 시 입력값을 보존하고 원인 및 재시도 방법을 안내한다.
7. 웹 UI 반응형과 PDF 페이지 판형은 별개의 설계 항목으로 관리한다.

## 3. 사용자 작업 흐름

1. 서비스 접속 및 생성기 진입
2. 연도, 주 시작 요일, 언어 설정
3. 테마 선택
4. 주간·일간 페이지 및 노트 페이지 옵션 설정
5. 설정 요약 검토
6. PDF 생성 요청
7. 검증 결과 확인
8. PDF 다운로드 및 미리보기 확인

## 5. 반응형 레이아웃 요구사항

**반응형 웹은 선택 기능이 아니라 필수 제품 요구사항이다.** CSS 미디어 쿼리만 적용하는 것이 아니라 터치·키보드·화면 크기·Safe Area를 고려한 사용성을 제공한다.

| 구분 | 뷰포트 기준 | 레이아웃 |
|---|---|---|
| Mobile | 320~767px | 단일 열, 세로 스크롤, 터치 중심 |
| Tablet | 768~1023px | 1~2열, 설정과 미리보기의 유연한 배치 |
| Desktop | 1024px 이상 | 설정과 요약/미리보기 병렬 배치, 콘텐츠 최대 폭 1120px 권장 |

### 모바일
- 좌우 기본 여백 16px, 모든 입력은 화면 너비에 맞춘다.
- Header → 설정 → 테마 → 페이지 옵션 → 요약 → 결과 순서로 배치한다.
- 테마 선택은 2열을 기본으로 하되 좁은 폭에서는 1열로 전환한다.
- 하단 고정 생성 버튼을 적용할 경우 Safe Area, 키보드, 스크롤 콘텐츠를 가리지 않도록 한다.
- 320px 폭에서 가로 스크롤 없이 핵심 기능을 사용할 수 있어야 한다.

### 태블릿
- 화면 폭에 따라 1열/2열을 전환한다.
- 터치 조작을 고려해 컨트롤 크기와 간격을 유지한다.
- 미리보기는 설정 아래 또는 보조 패널로 배치한다.

### 데스크톱
- 최대 1120px 컨테이너를 중앙 정렬한다.
- 설정 영역과 요약/미리보기 영역을 병렬 배치한다.
- 키보드 조작과 넓은 화면에서의 정보 위계를 유지한다.

### 웹 호환성
- 반응형 웹 UI는 설치형 앱이나 Electron 없이 브라우저에서 접속 가능해야 한다.
- 화면 폭에 따라 핵심 기능을 숨기거나 데스크톱 전용 동작을 강제하지 않는다.
- 지원 브라우저 범위는 배포 시점에 Chrome, Edge, Safari, Firefox의 최신 안정 버전을 기준으로 검증하고 확정한다.
- 네트워크 단절·API 오류·세션 만료 상태를 고려한다.

## 6. 화면 상세

### 6.1 설정 화면

| 필드 | UI | 검증 기준 |
|---|---|---|
| 연도 | 숫자 입력/선택 | Python 엔진의 허용 범위와 일치 |
| 주 시작 요일 | 라디오/세그먼트 | 엔진에서 지원하는 값 |
| 언어 | 선택 컨트롤 | 엔진에서 지원하는 언어 |
| 테마 | 선택 카드 | 엔진의 테마 허용 목록 |
| 주간 페이지 | 체크/스위치 | boolean |
| 일간 페이지 | 체크/스위치 | boolean |
| 노트 페이지 수 | 숫자 입력 | 엔진 허용 범위의 정수 |

기본값과 허용 범위는 Python 엔진을 단일 기준으로 삼는다. UI에 별도 상수를 둘 경우 엔진 검증 규칙과 동기화한다.

### 6.2 요약 및 미리보기
- 현재 설정값을 즉시 반영한다.
- 확정되지 않은 페이지 수를 확정값처럼 표시하지 않는다.
- 미리보기는 실제 생성된 이미지 또는 샘플임을 명시한 이미지로 구분한다.
- 결과 파일이 준비되기 전 다운로드 링크를 노출하지 않는다.

### 6.3 생성 상태 모델

| 상태 | 의미 | UI 처리 |
|---|---|---|
| idle | 대기 | 생성 액션 활성 |
| validating | 입력 검증 | 검증 안내 |
| submitting | 요청 전송 | 버튼 중복 실행 방지 |
| processing | PDF 생성 | 단계형 진행 안내 |
| verifying | 링크·산출물 검증 | 검증 단계 표시 |
| succeeded | 완료 | 결과 패널 노출 |
| failed | 실패 | 원인 및 재시도 안내 |

실제 진행률 데이터가 없으면 임의의 퍼센트를 표시하지 않는다. 생성 중에는 중복 요청을 차단한다.

### 6.4 결과
- 파일명, 다운로드 링크, 페이지 수, 링크 검증 결과를 표시한다.
- 엔진/API가 반환한 실제 값만 사용한다.
- 오류가 있으면 상세 원인과 재시도 가능 여부를 표시한다.
- 임시 파일 보관 정책이 적용되면 만료 시점을 안내한다.

## 8. 실행 아키텍처와 웹 지원

### 기존 데스크톱 경로
React UI → Electron preload/IPC → Python PDF 엔진

### 웹 브라우저 경로(구현 필요)
브라우저 React UI → HTTPS API → Python PDF 엔진 → 결과 파일/다운로드 응답

### 공통 설계
- UI는 플랫폼에 종속되지 않는 생성 설정 모델을 사용한다.
- 실행 어댑터가 Electron IPC와 Web API 호출을 분리한다.
- 웹에서는 Electron 전역 객체를 참조하지 않는다.
- API가 준비되지 않은 상태에서 웹 생성이 가능한 것처럼 표시하지 않는다.
- 업로드/다운로드 파일 크기, 요청 시간 제한, 오류 응답, 동시 생성 수, 임시 파일 정리 정책을 API 설계에 포함한다.
- 기존 Electron 경로의 기능 및 회귀 테스트를 유지한다.
- 인증·사용량 제한·파일 보관 정책은 배포 전 별도 결정한다.

## 9. UI 검증 시나리오 및 완료 기준

- [ ] 320, 360, 390, 768, 1024, 1440px 화면에서 레이아웃 검증
- [ ] PC·태블릿·스마트폰 브라우저에서 핵심 작업 흐름 수행
- [ ] 320px에서 가로 넘침 및 고정 CTA 가림 없음
- [ ] 입력값 변경 시 요약 동기화
- [ ] 잘못된 값에 구체적인 오류 표시
- [ ] 생성 중 중복 요청 차단
- [ ] 성공/실패/검증 상태 표시
- [ ] 키보드 접근 및 포커스 표시
- [ ] 실제 API 결과만 다운로드 링크로 제공
- [ ] Electron 기존 실행 경로 회귀 확인
- [ ] 모바일 브라우저에서 PDF 생성·다운로드·열기 실기기 검증

UI 반응형 완료와 웹 PDF 생성 완료를 별도로 판정한다. 웹 PDF 생성은 서버 API 배포와 브라우저 실기기 검증까지 완료해야 한다.

## 10. 미확정 및 후속 결정
- 웹 API 프레임워크·배포 위치·운영비
- 인증 및 생성 횟수 제한
- PDF 임시 저장소와 만료 정책
- 스마트폰용 세로형 PDF 판형
- 지원 브라우저 및 모바일 PDF 뷰어 범위
