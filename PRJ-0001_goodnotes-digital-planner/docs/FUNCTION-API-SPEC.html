PRJ-0001 · Product specification

Goodnotes Digital Planner

기능정의서와 API 설계 요약. 기존 Electron/Python 구현과 신규 웹 API 제안 범위를 구분한 실행 가능한 설계 기준 문서입니다.

01. 문서 개요

저장소의 실제 코드에서 확인한 동작과 신규 웹 API 설계 제안을 구분합니다.

현재 구현Electron IPC, Python CLI, ReportLab PDF 생성, PDF 링크 검증, 미리보기 모듈
신규 개발HTTPS API 서버, 작업 상태 조회, 웹 다운로드, 브라우저 실행 어댑터
반응형 목표Mobile 320–767px, Tablet 768–1023px, Desktop 1024px+
구현 상태 주의: 아래 REST API 경로는 설계 계약 제안이며 현재 운영 중인 API가 아닙니다. 설계 문서 작성만으로 웹 PDF 생성 기능이 구현되는 것은 아닙니다.

02. 제품 범위

포함 기능

  • 연도, 주 시작 요일, 언어, 테마 설정
  • 주간·일간 페이지 포함 여부 및 노트 페이지 수 설정
  • 연간·월간·선택형 주간·일간·노트 페이지 PDF 생성
  • PDF 내부 링크 및 파일 크기 검증
  • 생성 결과, 미리보기 및 다운로드 제공
  • PC·태블릿·스마트폰 반응형 UI
  • 기존 Electron 경로 유지 및 웹 API 경로 추가

후속 범위

계정·구독·결제, 클라우드 생성 이력, 세로형 모바일 PDF, 생성 취소·실시간 진행률은 별도 결정 대상으로 둡니다.

주요 기능 상세

  • 입력 검증: 필드별 오류를 표시하고 생성 전 차단. 클라이언트 검증만 신뢰하지 않습니다.
  • 생성: 작업별 임시 디렉터리에서 PDF 생성. 내부 경로를 사용자 응답에 노출하지 않습니다.
  • 검증: 깨진 링크, 페이지 수, 파일 크기를 확인합니다. 현재 코드에서 링크가 0개이면 검증 실패입니다.
  • 결과: 검증 통과 시에만 다운로드를 제공합니다. 미리보기 오류는 PDF 생성 성공 여부와 분리하는 것을 권장합니다.

05. 실행 아키텍처

기존 데스크톱 경로 코드 확인

React UI→window.planner.generate→Electron preload / IPC→Python CLI→ReportLab PDF

IPC 채널은 planner:generate이며, main 프로세스가 python -m engine.cli를 실행합니다.

웹 브라우저 경로 신규 제안

Browser React UI→HTTPS REST API→작업 큐/워커→Python 엔진→검증/파일 저장→다운로드

웹은 Electron IPC를 호출할 수 없으므로 API 서버와 파일 제공 경로가 필요합니다.

07. API 요청·응답 예시

작업 생성: POST /api/v1/generations

HTTP/1.1 202 Accepted
{
  "generationId": "uuid",
  "status": "queued",
  "statusUrl": "/api/v1/generations/uuid",
  "createdAt": "2026-11-21T10:00:00Z"
}

상태 조회: GET /api/v1/generations/{id}

{
  "generationId": "uuid",
  "status": "succeeded",
  "result": {
    "fileName": "planner_2027_ko_navy.pdf",
    "pageCount": 0,
    "linkCount": 0,
    "brokenLinkCount": 0,
    "sizeMb": 0,
    "validationPassed": true,
    "downloadUrl": "/api/v1/generations/uuid/download"
  }
}

위 숫자 0은 필드 구조를 보여주기 위한 예시값이며 실제 플래너 생성 결과가 아닙니다. 실제 응답은 엔진 반환값을 사용합니다.

검증 오류 예시

HTTP/1.1 422 Unprocessable Entity
{
  "code": "VALIDATION_ERROR",
  "message": "요청 설정을 확인해 주세요.",
  "errors": [
    {"field": "year", "reason": "2000~2100 사이 정수여야 합니다"}
  ],
  "requestId": "server-generated-id"
}

08. 작업 상태 모델

queued→validating→processing→verifying→previewing→succeeded

실패는 각 단계에서 failed로 전이합니다. 진행률 이벤트가 엔진에 구현되기 전까지 progress: null을 반환하며 UI에서 임의 퍼센트를 만들지 않습니다.

09. 보안 및 운영

  • 운영 환경 HTTPS 강제, CORS 허용 Origin 최소화
  • 입력 DTO allow-list 검증, 파일 경로와 실행 명령을 클라이언트에서 받지 않음
  • 작업별 격리 디렉터리, 서버 생성 파일명, Path Traversal 방지
  • 생성 시간·파일 크기·동시 작업 수 제한
  • 검증 성공 작업만 다운로드 허용, 사용자별 작업 소유권 검사
  • 내부 절대 경로·Traceback·토큰·비밀키는 응답에서 제외
  • 요청 ID를 이용해 서버 로그에서 상세 오류 추적

10. 인수 기준 및 테스트

  • 연도 경계(1999/2000/2100/2101), 잘못된 타입 검증
  • 요일·언어·테마 허용값 검증
  • 주간/일간 조합과 노트 페이지 경계 검증
  • PDF 페이지 수·링크·파일 크기 검사 및 실패 다운로드 차단
  • 웹 API 작업 등록·상태 조회·파일 다운로드 E2E
  • 320/360/390/768/1024/1440px 반응형 검증
  • Electron 기존 IPC 회귀 테스트
  • 네트워크 오류·만료 파일·요청 제한 오류 표시

11. 구현 전 확정할 사항

  1. notes=0일 때 0페이지를 생성할지 최소 1페이지를 유지할지.
  2. 링크 0개인 PDF를 검증 성공으로 인정할지.
  3. 웹 API 프레임워크 및 호스팅 플랫폼.
  4. 인증/사용량 제한 도입 시점.
  5. PDF 및 미리보기 보관 기간·삭제 정책.
  6. 생성 취소·실시간 진행률 이벤트 범위.
권장 개발 순서: 공통 DTO → 옵션/검증 API → 비동기 생성 워커 → 상태/다운로드 API → 미리보기 API → 인증·제한·보관 정책 → 반응형 웹 E2E.
